# 它怎麼思考？推論機制白話版

> 這份文件會解釋 OpenMythos 內部的推理邏輯，以及它為什麼比傳統 AI「更會想事情」。

---

## 傳統 AI 怎麼思考？

傳統的 Transformer（像早期的 GPT）可以想像成一條**流水線**：

```
輸入 → [第1層] → [第2層] → [第3層] → ... → [第N層] → 輸出
```

每一層都有自己獨特的「處理方式」，資料只會從頭到尾走一遍。  
好處是架構簡單、訓練穩定；壞處是如果你想讓它「想深一點」，就只能加更多層，而更多層 = 更多參數 = 更貴。

---

## OpenMythos 怎麼思考？三個階段

OpenMythos 把思考分成三段：

### 第一段：Prelude（前奏）— 理解問題

```
輸入文字 → 先經過幾層「理解層」
```

這個階段把原始的文字轉換成模型內部能處理的「向量表示」。  
你可以想像成：把題目讀懂，記在心裡，準備開始解題。

這個「記在心裡的東西」叫做 **`e`（encoded input，編碼後的輸入）**，之後每一輪思考都會把它帶著，確保不會跑題。

---

### 第二段：Recurrent Block（循環推理）— 反覆深想

這是最有趣的地方。模型會在這個區塊**反覆執行同一組參數**，最多執行 `max_loop_iters` 次（預設 16 次）：

```
第 1 輪：h₁ = A×h₀ + B×e + 推理結果
第 2 輪：h₂ = A×h₁ + B×e + 推理結果
第 3 輪：h₃ = A×h₂ + B×e + 推理結果
...
```

每一輪都在「上一輪的結論」基礎上繼續推理，而且每輪都會把原始問題 `e` 混進去，避免越想越跑偏。

這就像你解一道難題：
- 第 1 輪：讀懂題目，想出大方向
- 第 2 輪：在大方向上具體推算
- 第 3 輪：驗算、修正錯誤
- 第 N 輪：答案越來越收斂

---

### 第三段：Coda（尾聲）— 整理輸出

```
最終的 h → 幾層「整理層」→ 輸出答案
```

把循環推理的結果整理成可以輸出的文字。

---

## 幾個讓它更聰明的設計

### 1. 每一輪的「思考方式」不一樣 — 循環索引嵌入

問題來了：如果每輪都用同樣的參數，它怎麼知道自己在第幾輪？  
解法是加入一個「我現在在第幾輪」的信號（sinusoidal loop-index embedding）。

就像人類解題時，「第一遍讀題」和「第三遍驗算」的心態不同，模型也能學到在不同輪次做不同的事。

### 2. 知道什麼時候停下來 — ACT 自適應停止

有時候問題很簡單，不需要想 16 輪。如果想了 3 輪就收斂了，繼續想下去反而可能「想太多」導致出錯。

ACT（Adaptive Computation Time）機制讓模型對每個詞語計算一個「我還需要繼續想嗎？」的機率：
- 簡單的詞語：早早停下，節省計算資源
- 困難的詞語：繼續循環，直到確定

這讓同一批輸入裡，不同難度的部分可以用不同深度的計算處理。

### 3. 訓練時不會爆炸 — LTI 穩定注入

循環這件事有個技術難題：每輪都把結果乘以 A 再加上去，如果 A 大於 1，就會不斷放大，最後變成無限大，模型訓練就崩了。

解法是強迫 **A 的特徵值一定小於 1**（用數學方式讓它永遠穩定）。  
這樣不管跑幾輪，數值都不會爆炸。

### 4. 同樣的參數，做不同的事 — 深度 LoRA

每輪使用完全一樣的參數，限制了模型的表達能力。  
LoRA 適配器解決了這個問題：在共用的大參數上，每一輪額外加一個「微調偏移量」。

- 大部分計算：全輪共用（省參數）
- 小部分調整：每輪不同（增加靈活度）

### 5. 廣度靠專家分流 — MoE 混合專家

光靠深度（循環次數）能讓模型「想得更深」，但不能讓它「懂更多領域」。  
MoE（Mixture of Experts）解決廣度問題：

- 把 FFN（前饋神經網路）拆成很多個「小專家」
- 每個詞語只呼叫其中幾個最適合的專家
- 有一些「共用專家」每次都會呼叫，處理通用知識

結果：模型可以有很多「專長」，但每次計算只用到一小部分，不會很浪費。

## 為什麼這個方式更好？

| 能力 | 傳統 Transformer | OpenMythos |
|---|---|---|
| 解多步驟問題 | 需要更多層（更多參數） | 增加循環次數即可 |
| 測試時挑戰更難的問題 | 做不到 | 增加 `n_loops` 參數就行 |
| 計算資源分配 | 每個詞平等對待 | 簡單的詞用少，難的詞用多 |
| 參數效率 | 多少層就多少參數 | N 層循環 L 次 ≈ NL 層的效果 |

```
         ┌─────────────────────────────────────────┐
         │           OpenMythos 思考流程            │
         └─────────────────────────────────────────┘

  輸入文字
     ↓
 [Prelude] — 讀懂問題，得到 e（記住原始問題）
     ↓
 [循環推理，最多 16 輪]
  ┌──────────────────────────────────────┐
  │  h_新 = A×h_舊 + B×e + 本輪推理結果  │
  │  ↑ 把之前的想法 ↑ 記住原問題 ↑ 新想法  │
  │                                      │
  │  如果這個詞夠確定了 → 提早停止（ACT） │
  └──────────────────────────────────────┘
     ↓
 [Coda] — 整理最終思考結果
     ↓
  輸出答案
```
