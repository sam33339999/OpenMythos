執行摘要

本研究的核心張力，是兩種層級迥異、卻目標相似的收斂機制：單模型反覆運算（OpenMythos 迴圈深度）與多模型並行審議（OpenRouter Fusion）。兩者都在解同一個問題——「如何用多次計算換取更好的單一答案」，但「多次」的單位完全不同。

一句話結論 Mythos 在單一模型的連續潛在空間裡反覆運算，深度可外推、成本幾乎免費、靠譜半徑 ρ(A)<1 構造性保證收斂；Fusion 在多個模型之間透過自然語言協調，審議限於單層、成本線性增長、靠遞迴保護與三級降級容錯。兩者不是二選一的對立，而是同一個設計空間的兩個極點。

OpenMythos：深度來自「同一組權重跑很多次」

OpenMythos 是對 Claude Mythos 模型架構的「理論重構」（theoretical reconstruction），純粹基於公開研究與推測，不附屬於也不受 Anthropic 背書。它實作的核心假設是：Claude Mythos 疑似是一個 RDT——與其堆疊數百層獨特層，它把其中一部分層回收、在同一個前向傳遞中跑多次。相同的權重、更多的迴圈、更深的思考。

關鍵在於這不是 chain-of-thought（CoT，思維鏈）。過程中沒有中間 token 輸出，所有推理都在單一次前向傳遞裡、於連續潛在空間（continuous latent space）中「沉默地」完成。此假設有四條支撐論證：

論證意涵
系統化泛化（systematic generalization）迴圈 Transformer 能處理訓練時沒見過的知識組合；能力是「相變」式出現
深度外推（depth extrapolation）訓練 5 步推理、測試 10 步仍能成功——靠推理期跑更多迴圈
潛在思考 = 隱式 CoT每個迴圈約等於一步 CoT，但在連續空間進行；可同時編碼多條路徑
無參數爆炸（no parameter blow-up）k 層跑 L 次可達 kL 層品質，但參數量只有 k 層

架構採三階段分工：前奏（Prelude）→ 迴圈區塊（Recurrent Block）→ 尾奏（Coda）。其核心更新規則為 h_{t+1} = A·h_t + B·e + Transformer(h_t, e)，其中凍結的編碼輸入 e 在每個迴圈以 B·e 重新注入，防止隱藏狀態漂移。

OpenRouter Fusion：廣度來自「多個異質模型並行」

Fusion 是一個伺服器端工具（server tool），任何模型都可呼叫。被呼叫時，一組模型（panel，最多 8 個）並行回答，附帶網路搜尋能力；一個判斷模型（judge）比對而非合併（compares, not merges）它們的回應，產出結構化 JSON（共識／矛盾／洞見／盲區），最後由你的模型（outer）撰寫最終答案。

關鍵設計決定 Fusion 被「設計成單層」——遞迴保護（recursion guard）禁止 panel 與 judge 再呼叫自己。每次呼叫帶 x-openrouter-fusion-depth header 標記深度，plugin 拒絕第二次注入。這與 Mythos「鼓勵無限加迴圈」形成最尖銳對比：連續空間靠穩定性條件自然收斂可深，離散呼叫空間成本指數成長必須淺。

研究收斂：設計空間的兩個極點

經過理論整合，本研究提出「疊代收斂器」（iterative convergence operator）的統一抽象，把兩者都視為「把外部視角融進推理狀態」的收斂算子。Part IV 的設計文件綜合全部證據，回答：「如果我要從零打造一個具備 Mythos 式響應與回授的 LLM，該從哪裡開始、要做哪些決定？」每一條設計建議都回指前篇證據，確保可追溯、可驗證。

Part I 緒論：OpenMythos 專案與迴圈深度架構

Part I（對應原始研究第 1–10 篇）完整覆蓋 OpenMythos 的運行與架構。本章先建立研究對象與核心假設，後續各章沿資料流逐一拆解三階段架構、穩定性、注意力、MoE、迴圈分化、ACT 與生成。

1. 這是什麼專案

OpenMythos 是一個 Python + PyTorch 的研究函式庫，試圖「理論重構」（theoretical reconstruction）Claude Mythos 模型的架構。套件目錄為 open_mythos（底線），發布名為 open-mythos（連字號）。它實作的是一種迴圈深度 Transformer（RDT），又稱 Looped Transformer，純粹基於公開研究與推測的社群重構。

它的核心假設（The Central Hypothesis）：Claude Mythos 疑似是一個 RDT。與其堆疊數百層獨特層，它把其中一部分層回收、在同一個前向傳遞中跑多次。關鍵差異在於這不是 chain-of-thought——過程中沒有中間 token 輸出，所有推理都在單一次前向傳遞裡、於連續潛在空間中「沉默地」完成。

3. 三階段架構總覽

OpenMythos 類別（main.py:899-924）將運算分成三個功能區塊：

[Prelude 前奏]   — prelude_layers 個標準 TransformerBlock，只跑一次
      ↓
[Recurrent Block]— 同一個 TransformerBlock 迴圈 T 次，每次注入 e
      ↑_______↓    h_{t+1} = A·h_t + B·e + Transformer(h_t, e)
      ↓
[Coda 尾奏]      — coda_layers 個標準 TransformerBlock，只跑一次
      ↓
輸出 logits

更新規則中，e 是 Prelude 結束後被凍結的編碼輸入，在每一個迴圈步都重新注入，用來防止隱藏狀態隨深度漂移。這個「持續注入原訊號」的設計，正是本系列後半對照 OpenRouter Fusion「整合」機制時的核心錨點（見 Part III 第 17 篇映射）。

4. 三階段資料流：Prelude → Recurrent → Coda

OpenMythos.forward（main.py:992-1034）是唯一的前向入口。三個階段在 __init__ 中被組裝：prelude 與 coda 是 nn.ModuleList（稠密 FFN），recurrent 是單一個 RecurrentBlock（內含 MoE FFN）。注意 Prelude 與 Coda 不用 MoE，只有 Recurrent Block 內的 TransformerBlock 用 MoE。

5. Recurrent Block 的五步管線

RecurrentBlock.forward（main.py:825-891）跑最多 n_loops 次迭代，每次執行以下五步管線。每個子步對應一個專題（見後續各章）：

for t in range(n_loops):
    h_loop = loop_index_embedding(h, t, self.loop_dim)  # (a) 迴圈索引嵌入
    combined = self.norm(h_loop + e)                    # (b) 加凍結 e 再正規化
    trans_out = self.block(combined, freqs_cis, mask,   # (c) TransformerBlock
                           kv_cache, cache_key=...)
    trans_out = trans_out + self.lora(trans_out, t)     # (d) 深度 LoRA 微調
    h = self.injection(h, e, trans_out)                 # (e) LTI 穩定更新
    p = self.act(h)                                     # (f) ACT 停止機率
    ... 累積權重、提早結束 ...

6. 兩個隱性不變量

權重共享 LM head 與嵌入表共享權重（main.py:956），test_weight_tying 驗證。整個 RecurrentBlock 是一個 TransformerBlock 實例跑 n_loops 次——這是「k 層參數、kL 層品質」的來源。
有快取時不提早結束 RecurrentBlock.forward 的提早結束有條件：if halted.all() and kv_cache is None: break。一旦有 KV 快取（生成模式），每個迴圈深度都必須跑完，後續解碼步才能在每個 cache_key 找到已填入的鍵。

KV 快取用字串鍵區分各層，避免碰撞："prelude_0"、"recurrent_loop_3"、"coda_1" 等。這套命名對自迴歸生成至關重要（第 11 章）。

7. 為什麼 Prelude/Coda 不用 MoE

「路由廣度」的價值在反覆推理的迴圈內——隱藏狀態 h_t 跨迴圈演化，router 在每個深度可能選到不同專家子集（第 9 章）。Coda 只跑一次，MoE 的稀疏路由好處有限，稠密 FFN 更直接。Prelude 的職責是把嵌入後的 token 序列「預處理」成穩定、資訊充分的表示 e；先讓 Prelude 用注意力融上下文，e 才攜帶「這整段輸入在說什麼」的語意。

11. LTI 穩定注入與譜半徑

RecurrentBlock 的第 (e) 步 h = A·h + B·e + trans_out 是穩定性的樞紐。本章拆解 LTIInjection 如何用動態系統理論讓這個遞迴「構造性地」永不發散——這是整個 OpenMythos 能被訓練起來的數學根基。

12. 為什麼迴圈訓練會不穩定

README「The Stability Problem」列出兩個主要失敗模式：殘差爆炸（隱藏狀態隨迴圈無界增長）與 Loss 尖峰（注入參數譜範數過大，訓練突然發散）。直觀原因：遞迴 h_{t+1} = A·h_t + … 把 A 反覆相乘，若 A 的特徵值有任何一個絕對值 ≥ 1，對應分量就以該特徵值為底呈指數增長，T 次後爆炸。

忽略非線性的 Transformer 項，遞迴退化為離散線性非時變（LTI）系統：h_{t+1} = A·h_t + B·e。對此系統，穩定性完全由 A 的譜半徑 ρ(A) := max |λ_i(A)| 決定：ρ(A) < 1 則穩定收斂，ρ(A) ≥ 1 則不穩定發散。

13. 構造性保證：ρ(A)<1 在數學上不可能被違反

LTIInjection 不靠正則化或梯度懲罰來「鼓勵」穩定，而是用參數化讓 ρ(A)<1 在數學上不可能被違反。做法分三步：

# 步驟一：A 參數化為連續負對角矩陣
A_continuous = Diag(-exp(log_A))     # log_A 可學，對角元素恆負

# 步驟二：ZOH（零階保持）離散化
A_discrete = exp(Δt · A_continuous)  # Δt = exp(log_dt) > 0，值落在 (0, 1)

# 步驟三：log 空間計算避免數值 NaN
def get_A(self):
    return torch.exp(-torch.exp((self.log_dt + self.log_A).clamp(-20, 20)))

關鍵數學鏈：log_A 任意實數 → exp(log_A) > 0 → -exp(log_A) < 0（連續系統極點負實數，穩定）；Δt > 0；Δt·A_continuous 對角元素仍負；exp(負數) ∈ (0, 1)（離散特徵值嚴格在單位圓內 → ρ(A)<1）。在 log 空間相加可避免「0 × inf = NaN」的退化；.clamp(-20, 20) 保證任何梯度步長下都有限。

激進梯度後仍穩定——直接驗證 測試 test_spectral_radius_stable_after_large_grad_step 模擬 lr=1000 的 SGD 一步，然後斷言穩定性仍然成立。這正是「構造性保證」的含義——不依賴溫和的訓練設定。對角 A 可用 A.max() 當譜半徑（特徵值即對角元素），一般（非對角）矩陣必須用 torch.linalg.eigvals(A).abs().max()。

14. 更新規則的完整形式

forward（main.py:727-742）：return A * h + self.B * e + transformer_out。三項相加的語意：

項語意
A * h衰減項——每通道獨立衰減（對角），衰減率受 (0,1) 約束
self.B * e注入項——把凍結的 e 加回，防止漂移
transformer_out非線性推理貢獻（注意力＋MoE 輸出）

三者相加：衰減的舊狀態 ＋ 重新注入的原訊號 ＋ 本輪新推理。帶輸入的系統在 ρ(A)<1 時是 BIBO 穩定（bounded-input bounded-output）——持續注入有界訊號只會把狀態推向有界穩態，而非無界增長。這是「每迴圈注入 e 不爆炸」的數學根據（詳見 Part III 第 18 章）。

15. 注意力機制：MLA 與 GQA

注意力是可替換零件，靠 cfg.attn_type 分派（main.py:649）："mla" → MLAttention；"gqa" → GQAttention。兩者都遵守同一個 forward 簽名，對上層完全透明。

16. GQA：Grouped Query Attention

GQAttention 實作 Ainslie et al., 2023。query 頭數 n_heads 多於 key/value 頭數 n_kv_heads：每個 KV 頭被 n_heads // n_kv_heads 個 query 頭共享，把 KV 快取縮成該比例分之一，但保留完整 query 表達力。預設 16 query 頭 / 4 KV 頭，即快取省 4 倍。

RoPE 先於快取（不變量） GQA 先對 Q、K 做 RoPE，再寫入快取（main.py:236-243）。快取值已帶位置編碼，取出時不必重旋。若違反此順序，解碼時會對已旋轉的鍵再旋一次，破壞相對位置語意。MLA 同樣遵守（main.py:389-395）。
Flash Attention 2 選用 Flash Attention 只影響 GQAttention（不影響 MLA）。裝了 flash-attn 時原生支援 GQA（不需 repeat_interleave）；沒裝時靜默退回手動 SDPA，由 _HAS_FLASH_ATTN 旗標守護。透過 [flash] extra 安裝。

17. MLA：Multi-Latent Attention（DeepSeek-V2 風格）

MLAttention 是所有正式變體的選擇。核心洞見：與其快取完整的 K 與 V（各 n_heads × head_dim 每 token），不如把 KV 路徑壓縮過一個低秩潛在 c_kv，只快取這個潛在加上 RoPE 鍵；解碼時再用便宜的線性投影重建 K_nope 與 V。

# KV 路徑：壓縮 → 快取 → 重建
x → kv_down (dim → kv_lora_rank + qk_rope_head_dim)
     分成 c_kv（潛在，快取）與 k_rope_raw（跨頭共享）
k_rope = RoPE(expand(k_rope_raw))   ← 快取前套 RoPE
c_kv → kv_norm → kv_up → [k_nope | v]  每步重建
k = cat(k_nope, k_rope)  每頭

快取大小對比決定了 MLA 為何是大規模首選：

注意力每層每 token 快取
GQAn_kv_heads × head_dim × 2
MLAkv_lora_rank + n_heads × qk_rope_head_dim

量產規模下 MLA 約小 10–20 倍——在 1M 上下文（mythos_100b 以上）這是「能不能塞得進去」的差別，而非「省不省錢」。測試 test_mla_fewer_kv_cache_bytes 用最小配置（dim=64）就成立，說明 MLA 的快取優勢在很小規模就顯現。example.py 與單測偏好 GQA 是因為簡單、快；正式變體清一色 MLA——尺度決定了 KV 快取是主導成本。

18. MoE 前饋網路與專家路由

前饋網路（FFN）依位置選用：RecurrentBlock 內的 TransformerBlock 用 MoEFFN（稀疏路由＋共享專家）；Prelude/Coda 用稠密 SwiGLU（Expert）。這是「廣度」（跨領域能力）的來源，與迴圈提供的「深度」互補。

19. MoEFFN：兩類專家（DeepSeekMoE）

路由專家（routed experts）

  • n_experts 個小 FFN（預設 64）。
  • 每 token 由 router 選 top-n_experts_per_tok 個（預設 4）。
  • router 是 nn.Linear(dim, n_experts)。
  • 啟動比例 4/64 = 6.25%。

共享專家（shared experts）

  • n_shared_experts 個較大 FFN，恆啟動。
  • 寬度刻意放大為 expert_dim × n_experts_per_tok。
  • 吸收跨領域共用模式（語法、基本推理），避免路由專家重複學習。

20. 無輔助損失的負載平衡（DeepSeek-V3 技巧）

這是 MoEFFN.forward（main.py:508-516）最精巧的部分。關鍵在於 bias 只影響「選誰」，不影響「權重多大」：

logits = self.router(flat)                              # (B*T, n_experts)，無偏
scores = F.softmax(logits, dim=-1)
_, topk_idx = (logits + self.router_bias).topk(self.topk, dim=-1)  # 選擇時加 bias
topk_scores = scores.gather(-1, topk_idx)               # 但權重用無偏 scores
topk_scores = topk_scores / topk_scores.sum(dim=-1, keepdim=True)  # 重正規化

router_bias 是 buffer 不是參數（main.py:485），訓練時外部更新（用來把使用不足的專家更常選到）。選 top-K 時用 logits + router_bias，但 gating 權重取自無偏的 scores。因此 bias 永遠不出現在梯度裡——它只調整「派工」，不扭曲 loss 信號，避免了傳統 auxiliary loss 法會干擾主損失的問題。

MoE 與迴圈的乘法效應 隱藏狀態 h_t 跨迴圈演化，router 在每個深度可能選到不同專家子集，於是「每個迴圈計算上都是獨特的，即使共享權重」。深度（同一組權重反覆運算）× 廣度（每步從大專家池選小子集）= 極大的計算路徑多樣性，但參數量只來自一組共享層＋專家池。這也是 mythos_100b 以上能把專家數拉到 256–512、卻維持啟動比 ~1.5% 的原因。

21. 單一專家：SwiGLU

Expert（main.py:426-453）是基本積木：down(silu(gate(x)) * up(x))，即門控線性單元變體。它同時用作 MoE 內的個別路由專家，以及 Prelude/Coda 的稠密 FFN（後者 expert_dim = dim * 4 // 3）。測試 test_shared_experts_always_fire 用一個巧妙方式驗證共享專家具獨立貢獻：把所有路由專家權重清零，若輸出仍非零，表示共享專家具獨立貢獻。

22. 迴圈索引嵌入與深度 LoRA

共享權重要能「按深度分化」，否則被迫做萬能折衷。設想 TransformerBlock 跑 16 次，若每次輸入完全相同，權重只能學到「一個對所有深度都尚可的折衷」。OpenMythos 用兩個互補機制緩解：無參數的 loop_index_embedding 與少量參數的 LoRAAdapter。

23. 機制一：loop_index_embedding（無參數）

loop_index_embedding（main.py:541-570）在隱藏狀態的前 loop_dim 個通道注入正弦訊號。這與 RoPE 在序列位置的邏輯同構，只是把「序列位置 m」換成「迴圈深度 t」。特點：純函數無可學參數；只動前 loop_dim = dim // 8 通道，其餘不變；不同迭代產生不同輸出。在 RecurrentBlock 內是「先注入迴圈索引、再加 e、再 norm」——三個訊號在進注意力前就疊好。

def loop_index_embedding(h, loop_t, loop_dim, theta=10000.0):
    freqs = 1.0 / (theta ** (torch.arange(0, loop_dim, 2, ...) / loop_dim))
    angles = loop_t * freqs
    emb = torch.cat([angles.sin(), angles.cos()], dim=-1)[:loop_dim]
    emb_full = torch.zeros(h.shape[-1], ...)
    emb_full[:loop_dim] = emb
    return h + emb_full.unsqueeze(0).unsqueeze(0)

24. 機制二：LoRAAdapter（少量參數）

LoRAAdapter（main.py:578-619）源自 Relaxed Recursive Transformers（Bae et al., 2024）。它介於「純權重共享」與「每層獨立權重」之間：delta(x, t) = (down(x) * scale[t]) @ B。三個組件：down（Linear(dim, rank)）與 B（(rank, dim)）跨所有迴圈共享；scale（Embedding(max_loops, rank)）則每個迴圈一個元素級尺度向量。總參數開銷極小，但讓每個迴圈的有效變換略微不同。LoRA delta 加在 TransformerBlock 輸出上。

深度外推的關鍵：clamp（必須保留的不變量） LoRAAdapter.forward：t_idx = loop_t if loop_t <= max_t else max_t。推理時 n_loops 可以超過訓練的 max_loop_iters（深度外推），此時 Embedding 表沒有那麼多列，直接索引會越界。clamp 讓超出範圍的迭代重用最後一個學到的尺度，而非崩潰。這與 ACT 的「提早停止」互補：訓練範圍內靠 ACT 決定何時停，訓練範圍外靠 clamp 不讓 LoRA 越界。

26. ACT 自適應計算時間

「更多迴圈」並非總是更好——超過某個深度，過度遞迴會降低預測（隱藏狀態漂過解答進入雜訊，即 overthinking）。ACTHalting（main.py:750-780）讓每個位置獨立決定何時停止累積更新——極簡（一個線性層加 sigmoid），從當前隱藏狀態預測「本步停止機率」p。

27. ACT 剩餘機率技巧與 still_running 閘門

真正的學問在 RecurrentBlock.forward 的累積邏輯（main.py:865-883）。採用 Graves (2016) 的標準「remainder trick」，確保輸出是「跨迴圈隱藏狀態的加權和，權重和為 1」：

p = self.act(h)                          # 本步停止機率 (B,T)
still_running = ~halted                  # 還沒停的位置
remainder = (1.0 - cumulative_p).clamp(min=0)    # 剩餘機率質量
weight = torch.where(
    cumulative_p + p >= self.cfg.act_threshold,  # 若累積+本步跨過門檻…
    remainder,                                   # …就把剩餘全給它（最後一步）
    p,                                           # 否則給本步機率
)
weight = weight * still_running.float()          # 已停位置權重歸零
h_out = h_out + weight.unsqueeze(-1) * h         # 加權累加
OpenMythos 特有的修正：still_running 閘門 若不乘上 still_running，已停止位置的 remainder 在停止後仍 > 0，會被重複加進 h_out，破壞「只貢獻一次」的語意。這個閘門確保每個位置恰好在停止那步貢獻完剩餘質量，之後靜默。

28. ACT 帶來的性質與門檻取捨

三個性質

  1. 逐位置自適應：同 batch 內簡單 token 早停、困難 token 跑滿深度，理論可帶來 2–3× 吞吐。
  2. 防過度思考：收斂後停止累積，避免漂進雜訊。
  3. 理論 Turing 完備：Graves (2016) 證明 ACT 讓模型 Turing 完備。

門檻取捨

act_threshold 預設 0.99（所有變體一致）。越接近 1：位置傾向跑更多步（更深推理），但更易過度思考；越低：提早停止更激進，省計算但可能沒想透。0.99 偏「讓它多想」，與 RDT「靠深度取勝」的哲學一致。

29. KV 快取與自迴歸生成

OpenMythos.generate（main.py:1036-1085）用 KV 快取把解碼成本從 O(T²) 降到 O(T)/步。三個關鍵設計：第 0 步吃整段 prompt，之後只吃一個 token；start_pos 控制 RoPE 切片；kv_cache 是同一個 dict 跨步累積。每個迴圈深度有獨立 cache_key（"recurrent_loop_{t}"），所以有快取時即使全停也必須跑完所有迴圈，保證每個深度的鍵都被填入。

深度外推兌現 訓練用 max_loop_iters，測試時可傳更大的 n_loops。這靠兩個第 10 章談過的機制：loop_index_embedding 是純函數（任意定義域）；LoRAAdapter 的 clamp（不越界）。generate(..., n_loops=8) 可在生成時全域調整「思考深度」——簡單任務調小省時、困難任務調大求質。取樣用 temperature + top-k。

Part II 緒論：OpenRouter Fusion 多模型審議

Part II（對應原始研究第 11–15 篇）轉向一個截然不同的機制。Part I 用十篇拆解了 OpenMythos 的「單模型反覆運算」；從此起是「多模型並行、judge 收斂」。openrouter:fusion 伺服器端工具賦予任何模型多模型審議（multi-model deliberation）能力。

31. Fusion 是什麼

當你的模型判斷某個 prompt 值得多方視角時，它呼叫此工具——一組模型（panel，最多 8 個）並行回答，附帶 web_search 與 web_fetch；一個判斷模型（judge）比對回應，產出結構化分析，最後由你的模型寫出最終答案。

32. 五階段管線詳解

  1. 注入工具：若用 model: "openrouter/fusion" 別名，router 把別名解析成真實模型並掛上 openrouter:fusion 工具。
  2. 模型決定是否呼叫：你的模型讀完 prompt，自己判斷這題值不值得「多方視角」。
  3. Panel 並行回答：一組模型同時回答，每個都帶 web_search 與 web_fetch。
  4. Judge 比對（不融合）：judge 收到所有 panel 回應，比對而非合併（compares, not merges），產出結構化 JSON。
  5. 你的模型寫最終答案：拿到結構化分析後，由你的模型（outer）撰寫最終回覆。
關鍵語意區別 judge 是 compares, not merges——它不做加權平均或多數決；它把「多數模型同意的」當高信心共識、標出分歧、保留單一模型的獨特洞見、點出無人涵蓋的盲區。最終答案由你的模型基於這份分析寫出，所以「結果不是簡單多數決」。

Server Tool 的獨特優勢：因為 tools 是陣列，可以讓同一個模型同時擁有 fusion、web_search、自訂函式呼叫等工具，由模型自己調度。Router 別名只注入 fusion 一個工具，所以 tool_choice: "required" 等同強制 fusion。回應的 model 欄位回報實際處理請求的模型，要查 generation metadata 的 router 欄位才知是否走 Fusion。

judge 恆為 temperature 0 你設的 temperature 只影響 panel，不影響 judge。比對必須可重現、不摻隨機。這與 OpenMythos 的 LTI 注入「構造性穩定」有異曲同工之妙：兩者都把「該確定的部分釘死」。另：web 工具（web_search/web_fetch）在 panel 與 judge 兩端都啟用，不是只有 panel 能查網路。

judge 產出的 analysis 物件有五個欄位，各自有明確語意。關鍵字是 compares rather than merges：judge 不把回應糊在一起，而是分類、標註出處、保留分歧。這讓 outer 模型拿到的是「附帶可信度標籤的證據集」，而非「失真的平均」。

38. Preset 體系、成本與遞迴保護

Preset（<task>-<tier>）

  • general-high：最強全用途 panel
  • general-budget：便宜 panel＋前沿 judge
  • general-fast：延遲同質 panel＋前沿 judge

顯式 analysis_models 或 model 永遠蓋過 preset。openrouter/fusion-flash ≡ general-fast 預設。

成本（線性）

1（outer）＋ N（panel）＋ 1（judge）。預設 N=3 → 約 4–5× 單次成本。要省就縮 N 或用 budget preset。

對照 Mythos：加迴圈的邊際成本是「同一組權重多跑一次前向」，參數不增長；Fusion 加 panel 是「多呼叫一個完整模型」，線性增加。

遞迴保護：Fusion 為何是單層 每次 fusion 呼叫帶 x-openrouter-fusion-depth header 標記深度。panel 與 judge 模型不能再呼叫 openrouter:fusion——plugin 在注入工具時檢查 header，若已是內層呼叫就拒絕第二次注入。若允許遞迴，深度 d、分支 N 的樹會產生 O(N^d) 次呼叫，成本與延遲瞬間失控。Mythos 鼓勵「無限加迴圈」，Fusion 卻禁止 panel/judge 再呼叫自己——連續空間靠穩定性條件自然收斂可深，離散呼叫空間成本指數成長必須淺。

40. 三個關鍵反差

多樣性從哪來

Mythos 的「多樣視角」全部來自單一模型的內部分化（索引嵌入、LoRA、MoE 路由）——合成多樣性。Fusion 來自多個不同模型本身，天然帶不同偏見與強項——取樣既有異質性。

整合的表徵空間

Mythos 是純粹的張量算術，人類無法直接讀懂在想什麼——連續空間。Fusion 是 judge 產出的 JSON——符號空間，人類可直接檢視。連續適合模型內部訓練；符號適合跨模型編排與人類審計。

對「深度」的態度

Mythos 鼓勵深度（推理時可把 n_loops 調超過訓練值）。Fusion 禁止深度（遞迴保護限單層）。一個敢深、一個必須淺，原因都在成本與收斂性的本質差異。

41. 統一抽象：疊代收斂器

撇開實作，兩者都可抽象成同一個數學骨架——疊代收斂器（iterative convergence operator）：

給定初始狀態 s_0 與輸入 x
重複： s_{k+1} = F(s_k, x, views_k)
直到收斂或達上限
回傳 s_K

Mythos：F = LTI 注入＋TransformerBlock，views_k = 同一模型在第 k 迴圈的條件化輸出。Fusion：F = judge＋outer，views_k = N 個 panel 模型的回應（只疊代一次，單層）。這個抽象讓我們能用統一的動態系統語言談兩者（見下章），並在設計時有共同的設計詞彙：狀態、更新函數、視角來源、停止條件。

兩者其實在解同一族問題 儘管機制迥異，兩者適用的任務高度重疊：研究問題、跨領域批判、比較型任務、出錯成本高。差別只在在哪裡思考：Mythos 在單一模型的潛在空間裡沉默地、連續地；Fusion 在多個模型之間透過自然語言、顯式地。

42. 回授的數學基礎：LTI 動態系統

把 Mythos 的 RecurrentBlock 更新規則寫成標準形式，忽略非線性的 Transformer 項，得到離散線性非時變（LTI）系統：h_{t+1} = A·h_t + B·u_t（u_t = e，常數輸入）。這就是控制理論裡最基本的離散時間狀態空間模型——h 是狀態，A 是狀態轉移矩陣，B 是輸入矩陣。

43. 收斂的充要條件：譜半徑

對齊次系統 h_{t+1} = A·h_t，解為 h_t = A^t·h_0。「狀態不爆炸」的條件是 A^t → 0，這等價於譜半徑條件：ρ(A) := max |λ_i(A)| < 1。把 A 對角化後，A^t 每個對角元素是 λ_i^t，|λ_i| < 1 時該分量衰減到 0。

帶輸入的系統：為什麼「注入」不破壞穩定性 有輸入時若 ρ(A)<1，系統是 BIBO 穩定：齊次解衰減，特解 Σ A^k B u 因幾何級數收斂而有界。這正是「在每個迴圈注入 B·e 不會讓系統爆炸」的數學根據——只要 ρ(A)<1，持續注入有界訊號只會把狀態推向有界穩態附近。OpenMythos 的 e 來自 Prelude，是有限維張量，自然有界。

44. 非線性的考慮：三重保護

真實更新有 Transformer(h_t, e) 這個非線性項。嚴格說，譜半徑條件是對線性近似成立的。為什麼實務上仍可靠？OpenMythos 的穩定性是「線性構造保證＋非線性小增益＋ACT 安全閥」的三重保護：

  1. Lipschitz 上界：若 Transformer 塊是 Lipschitz 連續，且其常數 L 滿足 ρ(A) + L < 1（小增益條件），非線性系統仍有收斂保證。
  2. ACT 的安全閥：即使偶爾偏離，ACT 讓位置在收斂後停止，避免長期累積偏離。
  3. 經驗：lr=1e3 測試顯示，即使極端梯度步驟後 A 仍 < 1，且訓練收斂。

45. 把同一套語言套到 Fusion

Fusion 不是線性系統，但可視為單步迭代的動態系統：s_1 = F(s_0, x, {m_1(x), ..., m_N(x)})。它只疊代一次（遞迴保護），所以沒有「特徵值爆炸」的風險——不存在 A^t 的累乘。但若假設性地允許遞迴，收斂性完全取決於 F 的「譜半徑」（複合算子的 Lipschitz 常數），而這對自然語言 LLM 是未知且不可控的——這正是 Fusion 用硬性單層界來規避的根本原因。Mythos 靠構造保證 ρ<1 可以放心遞迴；Fusion 無此保證所以禁止遞迴。數學上完全一致。

持續注入訊號注入項有界嗎？系統 BIBO 穩定嗎？

46. 機制映射：注入 vs 整合

把 Fusion judge 的「結構化整合」逐項對應到 Mythos 的「B·e 注入」。兩者都是「把外部視角融進推理狀態」的收斂算子，在抽象上同構，在實作上分歧：

維度Mythos 注入Fusion 整合
視角來源單一同源（凍結 e）多個異質（panel 模型）
表徵空間連續張量（可微、可反傳）符號 JSON（可讀、可降級）

三個可互相借鏡的設計元素：(1) 讓 Mythos 迴圈狀態攜帶「分歧標記」（提升可解釋性）；(2) 為注入路徑加降級（視角失效時退回其他視角）；(3) 為 Fusion 整合加「反覆修正」（允許 outer 多輪消化 judge 分析，在受限深度內）。

47. 推理期計算擴展：迴圈數 vs 模型數

「test-time scaling」泛指推理時花更多計算換更好答案。OpenMythos 與 Fusion 代表兩個正交的軸：深度擴展（n_loops↑）與廣度擴展（panel 數 N↑），兩者可獨立調，理論上也能組合。

48. Mythos 深度：可預測的飽和指數衰減

Parcae 的 scaling laws 給出明確經驗規律：每多一個迴圈品質提升，但邊際增益遞減，呈飽和指數曲線，與 CoT 的「想更多步」邊際遞減同構。成本上，每加一個迴圈＝多跑一次 RecurrentBlock，參數量不變：

成本(n_loops) ∝ n_loops      （線性 FLOPs）
參數量(n_loops) = 常數        （不隨迴圈增）

這是 Mythos 最迷人的性質：推理期加深度「幾乎免費」（只花計算，不花記憶體／參數）。飽和的原因有二：ACT 讓多數位置在收斂後停止（加迴圈對已收斂位置無效）；過度思考讓超過某深度品質反而微降。關鍵是推理時可把 n_loops 調到超過訓練值（深度外推），曲線在訓練範圍之外仍延伸。

49. Fusion 廣度：線性成本、收益受異質性支配

總呼叫＝1（outer）＋ N（panel）＋ 1（judge），預設 N=3 → 約 4–5×。Fusion 文件沒給像 Parcae 那樣精確的 scaling law，但可從機制推論邊際遞減來源：異質性飽和（新加模型若與既有模型高度相似，邊際資訊量低）；盲區收斂（主要視角覆蓋後剩餘盲區很少）；judge 能力上限（比對 N 個回應的難度隨 N 增）。遞減速率取決於你選的模型有多異質，不像 Mythos 的指數衰減那樣可預測。

什麼時候該深、什麼時候該廣 單一領域、需多步推理（數學、規劃）→ 深（同源視角反覆修正足夠，成本幾乎免費）。跨領域、需異質觀點（研究、批判、比較）→ 廣（異質性是本質需求，單模型難以合成；並行性利於延遲）。出錯成本極高（醫療、法律）→ 廣＋深。低延遲 agent 輪次 → 廣（fast preset）。組合成本相乘（N×迴圈數），應先選主軸，再視需要補另一個。

51. 訓練與資料策略

訓練腳本 training/3b_fine_web_edu.py 用 FSDP＋AdamW 在 FineWeb-Edu 上預訓練 3B（seq_len 2048、目標 30B tokens、LR 3e-4 cosine decay、bf16）。目標 30B 是「Chinchilla 調整後」的——因為迴圈架構的有效計算量大於參數量暗示的。

Parcae 的核心發現：迴圈與資料的權衡 在固定 FLOP 預算下，「多迴圈＋少資料」比「少迴圈＋多資料」更省 loss。兩個軸（迴圈數、token 數）各有冪律，指數跨尺度一致。這是反直覺的——把計算花在「讓同一批資料被反覆深加工」比「看更多淺資料」更有效。證據：770M 參數的迴圈模型達到 1.3B 固定深度 Transformer 的下游品質——約一半參數達同品質。

迴圈模型結構上偏推理、弱記憶（looping improves reasoning but can hurt memorization）。緩解：looping-based regularization——對推理任務用強迴圈約束、對檢索任務放鬆。Fusion 端的「訓練」其實是編排——panel 與 judge 都是現成模型，成本在推理而非訓練。

53. 五條硬性不變量（設計憲法）

這些是前 20 篇反覆驗證的「犯了一定壞」的規則，設計時列為檢核表：

  1. 回授矩陣的譜半徑必須構造性 < 1——離散動態系統收斂 ⇔ ρ(A)<1。用連續負對角＋ZOH 離散化，或任何保證特徵值在單位圓內的參數化。驗證：torch.linalg.eigvals(A).abs().max() < 1。
  2. 持續注入的訊號必須有界——BIBO 穩定要求有界輸入。確認注入源不會產生無界值（如未正規化的累積量）。
  3. 位置式停止或硬性深度界——過度思考會讓品質變差。偏好可學的 ACT（按難度自適應），這是 Mythos 相對 Fusion 的獨特優勢。
  4. 若用 KV 快取，每個迴圈深度必須有獨立鍵且跑滿——提早跳出會讓某些深度的快取空缺，後續解碼找不到鍵。
  5. 若引入異質多源視角，必須有遞迴保護——離散 LLM 呼叫的遞迴成本指數成長、無收斂保證。用 header／旗標標記深度，拒絕二次注入。

(e) 穩定更新LTI A·h+B·e+trans更新規則如何保證收斂？
(f) 停止ACT要不要學停止機率？

替換選項：(a) 可換成可學嵌入（增參數）；(c) 注意力選擇依尺度；(d) 可不用 LoRA（犧牲分化）；(f) 可不用 ACT（固定深度，失去自適應與過度思考防護）。

55. 落地路線圖與常見陷阱

建議的推進順序

  1. 決定前提三問（錯了全盤重來）
  2. 寫下五條硬性不變量作為設計憲法
  3. 選骨架（內部深度／模型之間／混合）
  4. 決定五步管線的每步選項
  5. 定訓練策略（Parcae、優化器、平行）
  6. 定評估維度，先寫測試再寫實作
  7. 從最小尺度起步（小 dim、少迴圈）
  8. 逐步放大，每步重驗不變量
  9. 若混合，最後才加廣度層
  10. 持續監控：譜半徑、loss、負載、停止分布

十大常見陷阱

  1. 譜半徑用錯公式（一般 A 須 eigvals）
  2. RoPE 在快取之後才套（重旋）
  3. 有快取時提早結束（破壞一致性）
  4. LoRA 外推未 clamp（越界）
  5. 未設遞迴界（成本指數失控）
  6. judge 用高溫（比對不可重現）
  7. 盲目堆疊深度×廣度（成本相乘）
  8. 資料越多越好（忽略 Parcae）
  9. 忽略記憶／推理偏見
  10. optimizer 在 FSDP 前建（追蹤舊參數）

56. 設計的核心張力

一句話收斂 回授 LLM 的設計，本質是在「可訓練的連續深度」與「可解釋的符號廣度」之間，依任務、成本、可解釋性需求做有意識的取捨，並用構造性不變量保證不發散、用停止機制防過度思考。OpenMythos 與 OpenRouter Fusion 不是二選一的對立，而是同一個設計空間的兩個極點。
