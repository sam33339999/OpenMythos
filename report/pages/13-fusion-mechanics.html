35. Fusion 的三種入口

官方提供三種使用入口，明言「三者打的是同一條 pipeline」，但控制粒度、使用姿態、適用場景各異。選對入口是落地整合的第一步。

入口形式定位控制粒度
Fusion Routermodel: "openrouter/fusion"把整條管線當成一個「模型」用最省事，工具自動注入
Fusion Pluginplugins: [{id: "fusion", ...}]在已有 model 上掛「設定面板」中等，可選 preset 與模型
Server Tooltools: [{type: "openrouter:fusion", ...}]直接宣告工具，模型自行決定何時呼叫最高，可搭配其他工具

Server Tool 的獨特優勢：因為 tools 是陣列，可以讓同一個模型同時擁有 fusion、web_search、自訂函式呼叫等工具，由模型自己調度。Router 別名只注入 fusion 一個工具，所以 tool_choice: "required" 等同強制 fusion。回應的 model 欄位回報實際處理請求的模型，要查 generation metadata 的 router 欄位才知是否走 Fusion。

judge 恆為 temperature 0 你設的 temperature 只影響 panel，不影響 judge。比對必須可重現、不摻隨機。這與 OpenMythos 的 LTI 注入「構造性穩定」有異曲同工之妙：兩者都把「該確定的部分釘死」。另：web 工具（web_search/web_fetch）在 panel 與 judge 兩端都啟用，不是只有 panel 能查網路。

36. 結構化分析的五個欄位

judge 產出的 analysis 物件有五個欄位，各自有明確語意。關鍵字是 compares rather than merges：judge 不把回應糊在一起，而是分類、標註出處、保留分歧。這讓 outer 模型拿到的是「附帶可信度標籤的證據集」，而非「失真的平均」。

欄位語意對 outer 模型的用處
consensus多數模型一致的論點，視為高信心可放心採信、寫進答案
contradictions模型間的分歧，附帶各方立場與出處需 outer 裁決或並陳
partial_coverage只有部分模型涵蓋的點提示某論點證據不足
unique_insights單一模型的獨特洞見值得考量但未必代表共識
blind_spots全體 panel 都沒談的主題提示答案可能的缺口

37. 三級降級處理

Fusion 的容錯設計是最值得借鏡的工程細節之一——「降級而非中斷」：

部分 panel 失敗 至少一個成功時仍 status: "ok"，附 failed_models 陣列說明誰失敗、為何。outer 可基於成功的回應繼續。
Judge 失敗（degradation） panel 成功但 judge 失敗時，工具不報錯，回 status: "ok" 並省略 analysis，只給原始 panel responses。
硬失敗 只有「無法產出任何有用輸出」時回 status: "error"，附型別化 failure_reason（all_panels_failed / insufficient_credits / rate_limited / fusion_invocation_capped / unexpected_error）。

38. Preset 體系、成本與遞迴保護

Preset（<task>-<tier>）

  • general-high：最強全用途 panel
  • general-budget：便宜 panel＋前沿 judge
  • general-fast：延遲同質 panel＋前沿 judge

顯式 analysis_models 或 model 永遠蓋過 preset。openrouter/fusion-flash ≡ general-fast 預設。

成本（線性）

1（outer）＋ N（panel）＋ 1（judge）。預設 N=3 → 約 4–5× 單次成本。要省就縮 N 或用 budget preset。

對照 Mythos：加迴圈的邊際成本是「同一組權重多跑一次前向」，參數不增長；Fusion 加 panel 是「多呼叫一個完整模型」，線性增加。

遞迴保護：Fusion 為何是單層 每次 fusion 呼叫帶 x-openrouter-fusion-depth header 標記深度。panel 與 judge 模型不能再呼叫 openrouter:fusion——plugin 在注入工具時檢查 header，若已是內層呼叫就拒絕第二次注入。若允許遞迴，深度 d、分支 N 的樹會產生 O(N^d) 次呼叫，成本與延遲瞬間失控。Mythos 鼓勵「無限加迴圈」，Fusion 卻禁止 panel/judge 再呼叫自己——連續空間靠穩定性條件自然收斂可深，離散呼叫空間成本指數成長必須淺。
