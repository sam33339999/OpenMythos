# 01 — OpenMythos 專案總覽與核心假設

> 研究系列首篇。本文確立研究對象、核心假設與後續 20 篇文件的論述起點。

## 1. 這是什麼專案

OpenMythos 是一個 **Python + PyTorch** 的研究函式庫，試圖「理論重構」(theoretical reconstruction)
Claude Mythos 模型的架構。套件目錄為 `open_mythos`（底線），發布名為 `open-mythos`（連字號）
（見 `pyproject.toml:7-8`，`name = "open-mythos"`, `version = "0.5.0"`）。

它實作的是一種 **Recurrent-Depth Transformer（RDT，迴圈深度 Transformer）**，又稱 Looped Transformer。
README 開宗明義說明它「不附屬於、也不受 Anthropic 背書」(`README.md:30`)，純粹是基於公開研究與推測的社群重構。

## 2. 核心假設：為什麼「迴圈」能解釋 Mythos

README 的「The Central Hypothesis」(`README.md:180-184`) 給出中心論點：

> Claude Mythos 疑似是一個 RDT。與其堆疊數百層獨特層，它把**其中一部分層回收、在同一個前向傳遞中跑多次**。
> 相同的權重、更多的迴圈、更深的思考。

關鍵差異在於：這**不是 chain-of-thought（CoT）**。過程中**沒有中間 token 輸出**，
所有推理都在單一次前向傳遞裡、於連續潛在空間 (continuous latent space) 中「沉默地」完成 (`README.md:182-184`)。

這個假設有四條支撐論證（`README.md:236-266`），摘要如下：

| 論證 | 意涵 |
|------|------|
| 系統化泛化 | 迴圈 Transformer 能處理訓練時沒見過的知識組合；能力是「相變」式出現的 |
| 深度外推 | 訓練 5 步推理、測試 10 步仍能成功——靠的是推理期跑更多迴圈 |
| 潛在思考 = 隱式 CoT | 每個迴圈 ≈ 一步 CoT，但在連續空間進行；可同時編碼多條路徑（接近廣度優先） |
| 無參數爆炸 | k 層跑 L 次可達 kL 層的品質，但參數量只有 k 層 |

這四點構成本系列後續探討「回授機制」的理論根基。

## 3. 程式碼的事實地圖

實際探索 `open_mythos/` 目錄後，核心模組如下（已逐一讀取確認）：

| 檔案 | 角色 | 關鍵類別 |
|------|------|----------|
| `open_mythos/main.py` | **正典實作**，所有公開匯出來自此處 (`__init__.py:1-17`) | `OpenMythos`, `MythosConfig`, `RecurrentBlock`, `LTIInjection`, `ACTHalting`, `MoEFFN`, `MLAttention`, `GQAttention`, `LoRAAdapter`, `RMSNorm` |
| `open_mythos/variants.py` | 預設尺度變體 | `mythos_1b` … `mythos_1t`（共 7 個，`variants.py:9-198`） |
| `open_mythos/tokenizer.py` | HF 分詞器包裝 | `MythosTokenizer`（預設 `openai/gpt-oss-20b`，`tokenizer.py:3`） |
| `open_mythos/moda.py` | **獨立的實驗性** MoDA（Mixture-of-Depths-Attention + DeepSeek-MoE）模型，**未**被 `__init__.py` 匯出，不接在 OpenMythos 上 |

> ⚠️ `AGENTS.md`（本倉庫的代理指引）特別警告：`main.py` 與 `moda.py` 是兩套平行實作，**不可混為一談**。
> 本系列研究聚焦在正典的 `main.py`（即 OpenMythos RDT）。

### 一個必須記住的已知瑕疵

`open_mythos/__init__.py:52-53` 把 `load_tokenizer` 與 `get_vocab_size` 列入 `__all__`，
但**從未匯入或定義它們**。因此 `from open_mythos import load_tokenizer` 會直接 `ImportError`。
研究與設計時不應依賴這兩個名字（`AGENTS.md`「Known doc/code mismatches」一節已記載）。

## 4. 三階段架構總覽（後續各篇會深入）

`OpenMythos` 類別 (`main.py:899-924`) 將運算分成三個功能區塊：

```
輸入 tokens
     ↓
[Prelude 前奏]   — prelude_layers 個標準 TransformerBlock，只跑一次
     ↓
[Recurrent Block]— 同一個 TransformerBlock 迴圈 T 次，每次注入輸入 e
     ↑_______↓    h_{t+1} = A·h_t + B·e + Transformer(h_t, e)
     ↓
[Coda 尾奏]      — coda_layers 個標準 TransformerBlock，只跑一次
     ↓
輸出 logits
```

更新規則 (`README.md:205-217`)：
```
h_{t+1} = A·h_t + B·e + Transformer(h_t, e)
```
其中 `e` 是 Prelude 結束後被**凍結**的編碼輸入，在**每一個迴圈步**都重新注入，
用來防止隱藏狀態隨深度漂移。這個「持續注入原訊號」的設計，正是本系列後半對照
OpenRouter Fusion「整合」機制時的核心錨點（見第 17 篇）。

## 5. 本文結論與下篇預告

- OpenMythos 是一個**單模型、反覆運算**的架構：深度來自「同一組權重跑很多次」。
- 它的「回授」是**隱藏狀態的時間遞迴**，不是多個模型之間的訊息往來。
- 這與 OpenRouter Fusion 的「**多模型並行、再由 judge 收斂**」形成鮮明對照——
  後者將在第 11 篇起詳述。
