# 10 — KV 快取與自迴歸生成

> 承接第 09 篇，Part I 壓軸。前九篇談的是「單次前向傳遞」；本文把它串成「逐 token 生成」。
> 焦點是 KV 快取如何把解碼成本從「整段序列」降到「每步一個 token」，以及
> 「推理時把 `n_loops` 調大」這個 RDT 獨有的 test-time scaling 如何落地。

## 1. 自迴歸生成的本質

語言模型生成是「給 prompt，逐個預測下一個 token，再把它接回輸入」。
樸素做法每步重算整段序列，成本 O(T²)。KV 快取把「已算過的鍵值」存下來，
每步只需算「新 token 一個」，成本降到 O(T)。

## 2. `generate()` 的解碼迴圈

`OpenMythos.generate`（`main.py:1036-1085`，`@torch.no_grad()`）的核心迴圈：

```python
# main.py:1066-1084
kv_cache: dict = {}
prompt_len = input_ids.shape[1]
for step in range(max_new_tokens):
    if step == 0:
        cur_ids = input_ids              # 第 0 步：整段 prompt
        start_pos = 0
    else:
        cur_ids = input_ids[:, -1:]      # 之後：只餵最後一個 token
        start_pos = prompt_len + step - 1
    logits = self.forward(
        cur_ids, n_loops=n_loops, kv_cache=kv_cache, start_pos=start_pos
    )
    logits = logits[:, -1, :] / temperature
    if top_k > 0:
        v, _ = logits.topk(top_k)
        logits[logits < v[:, -1:]] = float("-inf")
    probs = F.softmax(logits, dim=-1)
    next_tok = torch.multinomial(probs, num_samples=1)
    input_ids = torch.cat([input_ids, next_tok], dim=1)
return input_ids
```

三個關鍵設計：

1. **第 0 步吃整段 prompt，之後只吃一個 token**（`main.py:1069-1073`）。這是快取生效的前提。
2. **`start_pos` 控制 RoPE 切片**（`main.py:1020-1022`）：每步從預計算的 `freqs_cis` 裡切出對應位置的旋轉。
   prompt 長 + step 決定了當前 token 的絕對位置。
3. **`kv_cache` 是同一個 dict 跨步累積**（`main.py:1066`）：各層以字串鍵寫入，互不覆蓋。

## 3. KV 快取的內部結構

快取是個普通的 `dict`，鍵是層識別字串（`main.py:1026, 1032`，`main.py:860`）：

| 層 | cache_key | 內容 |
|----|-----------|------|
| Prelude 第 i 層 | `"prelude_{i}"` | GQA: `{"k":..., "v":...}`；MLA: `{"c_kv":..., "k_rope":...}` |
| RecurrentBlock 第 t 迴圈 | `"recurrent_loop_{t}"` | 同上（依 attn_type） |
| Coda 第 i 層 | `"coda_{i}"` | 同上 |

注意 **每個迴圈深度有獨立的 cache_key**（`main.py:860`）。這與第 04、09 篇強調的「有快取時跑滿所有迴圈」直接相關：
若提早跳出，某些 `recurrent_loop_{t}` 鍵就不存在，後續解碼步的注意力會找不到該深度的鍵，結果錯誤。

### MLA 快取 vs GQA 快取（第 06 篇的延續）

- GQA 存完整 K/V（`main.py:239-243`）。
- MLA 存壓縮潛在 `c_kv`（`kv_lora_rank`）+ `k_rope`（`main.py:391-395`），
  每步用 `kv_up` 重建 K_nope、V（`main.py:400-403`）。

測試 `test_mla_cache_is_compressed`（`tests/test_main.py:625-634`）與
`test_kv_cache_generate_matches_no_cache`（`tests/test_main.py:582-590`）共同保證：
快取路徑與無快取路徑在單 token 前向上數值一致（`atol=1e-4`）——這是快取正確性的硬性驗證。

## 4. 深度外推：推理時加迴圈數

RDT 最獨特的能力：訓練用 `max_loop_iters`，**測試時可傳更大的 `n_loops`**（`docs/open_mythos.md:202-209`）。

```python
# 訓練時 max_loop_iters=16；測試時試更深推理
logits_deep = model(input_ids, n_loops=32)
```

這之所以可行，靠兩個第 08 篇談過的機制：

1. **`loop_index_embedding`** 是純函數，定義域任意 `loop_t`，不越界。
2. **`LoRAAdapter` 的 clamp**（`main.py:612-617`）：超出訓練範圍的迭代重用最後一個學到的尺度。

測試 `test_depth_extrapolation_changes_output`（`tests/test_main.py:576-580`）驗證：
`n_loops=1` 與 `n_loops=3` 的輸出**必須不同**（深度有實際效果）。
`README.md:246-250` 把這連到「訓練 5 步推理、測試 10 步仍成功」的能力。

### `generate` 也吃 `n_loops`

`generate(..., n_loops=8)` 的預設是 8（`main.py:1041`），但每個解碼步都用同一個 `n_loops`。
這意味著可以在生成時全域調整「思考深度」——簡單任務調小省時、困難任務調大求質。

## 5. `forward` 對單 token 的處理

解碼步多數時候只傳 1 個 token（`T=1`）。`forward` 對此有特殊處理（`main.py:1023`）：

```python
mask = self._causal_mask(T, device, x.dtype) if T > 1 else None
```

`T=1` 時不建遮罩（單 token 無因果可言）。測試 `test_single_token_forward`（`tests/test_main.py:592-596`）
保證這不會崩潰。

遮罩 dtype 還有一個微妙點（`main.py:979-982` 註解）：遮罩的 dtype 必須與 activation 一致，
否則 additive 遮罩會把 bf16 權重的注意力 logits upcast 成 fp32，再與 bf16 的 V 做 matmul 時形狀/型別不符而出錯。

## 6. 取樣策略

`generate` 用 temperature + top-k 取樣（`main.py:1078-1083`）：

```
logits /= temperature
top_k 篩選：保留 top-K，其餘設 -inf
probs = softmax(logits)
next_tok = multinomial(probs)
```

- `temperature < 1`：分布更尖（更貪心）。
- `temperature > 1`：分布更平（更隨機）。
- `top_k=0`：停用篩選（全詞表取樣）。

沒有 top-p（nucleus）或 beam search——這是研究導向的極簡實作，足以示範生成迴圈。

## 8. 本文結論與下篇預告

- 生成靠 KV 快取把解碼降到 O(T)/步；每個迴圈深度有獨立 cache_key。
- MLA 快取壓縮潛在、GQA 快取完整 K/V，兩者都遵守 RoPE 先於快取。
- 深度外推靠 `loop_index_embedding`（任意定義域）+ LoRA clamp（不越界）。
- `generate` 用 temperature + top-k；全域 `n_loops` 控制思考深度。
- Part I 十大不變量已建立。
